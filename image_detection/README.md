# Qwen3-VL Image Tag Matching service

A local HTTP service that takes images plus the user's selected tags and returns, for each image and each tag, a match boolean, a confidence and a short evidence string. It implements the "Qwen3-VL Image Tag Matching — Build Spec". It handles model calls, image preprocessing, prompting, output parsing and caching. Page scraping, the tag picker and on-page highlighting live in the app.

```
app/extension ──POST /classify──▶ image_detection (127.0.0.1:8090) ──▶ llama-server (127.0.0.1:8080) ──▶ Qwen3-VL-8B Q8_0 + F16 mmproj
                                        │
                                        └── SQLite cache  data/cache.sqlite3
```

## Running it

1. **Start llama-server** (it needs to stay running):

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\start_llama_server.ps1
   ```

   By default this uses the newest CUDA 12 `llama-server.exe` bundled with LM Studio and loads
   `image_detection\LLM\Qwen3-VL-8B-Instruct-abliterated.Q8_0\` with the spec's flags (`-ngl 99 -fa on --jinja -c 16384 --parallel 2`).
   Options: `-Gpu 1` (index as in `nvidia-smi`), `-Ctx 8192`, `-Parallel 1`. Set `$env:LLAMA_SERVER_EXE` to use an official llama.cpp build instead.

2. **Start the service:**

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\start_service.ps1
   ```

   or `python -m image_detection --port 8090`. If you change `--parallel` on llama-server, set `LLAMA_PARALLEL` to the same value.

Requirements: Python 3.11+ with `fastapi uvicorn httpx pillow pydantic`. `pip install -e .[test]` installs them.

## API

### `POST /classify`

```json
{
  "images": [
    {"id": "img-1", "data_b64": "<base64 or data: URL>", "mime": "image/jpeg"},
    {"id": "img-2", "url": "https://example.com/photo.jpg"}
  ],
  "tags": [{"id": "man_blonde_hair", "rubric": "SUBJECT: ... REQUIRE: ... EXCLUDE: ... FALSE IF: ..."}],
  "threshold": 0.7
}
```

```json
{"results": {
  "img-1": {"status": "ok", "cached": false,
            "tags": {"man_blonde_hair": {"match": true, "confidence": 0.91, "evidence": "blond man at left"}}},
  "img-2": {"status": "error", "cached": false, "message": "fetch failed: HTTP 403"},
  "img-3": {"status": "skipped", "cached": false, "message": "short edge 50 px is below the minimum"}
}}
```

- `match` is already thresholded (`model_match AND confidence >= threshold`). The raw `confidence` is included so a UI slider can re-threshold without another call. To get the raw model answer, send `threshold: 0`.
- `cached` is `true` when every tag for that image came from the cache, meaning no model call was made.
- `status` is `ok`, `skipped` (short edge under 96 px, never sent to the model) or `error` (fetch, decode or model failure). A bad image never fails the batch.
- A single call takes at most 64 images. Tag ids must be snake_case (`[a-z0-9_]`, up to 64 characters) and unique.
- **HTTP 503 `{"error":"model server down"}`** means llama-server is unreachable or was stopped mid-run. The app should show a "start the model" message.
- For body-detail tags such as `woman_long_fingers`, the UI should default the threshold to **0.8**. The model is overconfident on small regions.

### `POST /expand_tag`

`{"text": "men with blonde hair"}` → `{"id": "men_with_blonde_hair", "rubric": "SUBJECT: ... REQUIRE: ... EXCLUDE: ... FALSE IF: ..."}`

Results are cached per normalized tag text. Show the rubric to the user and let them edit it before saving it.

**Adult rule (beyond the spec).** A tag about people is treated as adults only, unless its text names a child. A tag is about people if it uses words like woman, men, person, blondes or redheads, or if the generated SUBJECT describes a person. Child words are boy, girl, child, kid, teen, toddler, baby, infant and minor, plus their plurals. The rule is applied twice:
1. The expansion prompt asks the model to make SUBJECT an adult and to list "children or teenagers" under EXCLUDE. It also asks for at least three specific near-misses and gives the spec's `man_blonde_hair` rubric as a worked example.
2. `enforce_adult_subject()` in [rubrics.py](image_detection/rubrics.py) then checks the model's output. If SUBJECT doesn't say "adult", it adds "an adult, not a child or teenager". If EXCLUDE doesn't mention children, it adds "children or teenagers".

Rubrics the app sends to `/classify` are never rewritten. The rule only affects rubrics generated by `/expand_tag`. Changing the rule or the prompt means bumping `EXPANSION_VERSION` in `service.py`, so cached rubrics written under the old rule aren't reused. The service never stores app-side tags: the app sends `{id, rubric}` on every `/classify`.

### `GET /health`

`{"model": "Qwen3-VL-8B-Instruct-abliterated.Q8_0", "server": "up", "slots_free": 2, "stats": {"model_calls": 63, "retries": 0, "failures": 0}}`

`stats` goes beyond the spec. It counts model calls and JSON retries since startup.

### Using it as a Python library

```python
from image_detection import DetectionService, ImageInput, Tag, REFERENCE_RUBRICS

svc = DetectionService()                       # reads the same env vars
res = await svc.classify([ImageInput("a", data_b64=b64)],
                         [Tag("man_blonde_hair", REFERENCE_RUBRICS["man_blonde_hair"])])
```

## How it works

| Stage | Behaviour |
|---|---|
| Input | Uses base64 bytes if given. Otherwise fetches the URL server-side (10 s timeout, browser User-Agent). A failed fetch errors that image only. |
| Preprocess | Applies EXIF rotation and takes the first frame of animations. Skips the image if the short edge is under 96 px. Shrinks the long edge to `MAX_EDGE` without ever upscaling. Re-encodes as JPEG q90, or PNG if there is real transparency. |
| Identity | SHA-256 of the re-encoded bytes. |
| Cache | SQLite `(image_hash, rubric_hash, model_id)` → result. Only `ok` answers are cached. Tags that the model left out of its answer ("missing") are not cached. Editing a rubric invalidates only that tag. |
| Prompting | One image per call with up to `MAX_TAGS_PER_CALL` rubrics. Uses the verbatim system prompt from the spec. The user message lists the exact keys the answer must contain. Sends `temperature 0`, `max_tokens = 60 + 40×tags`, and a `json_schema` response_format so llama.cpp's grammar sampler enforces valid JSON. |
| Parsing | Strips markdown fences and parses from the first `{` to the last `}`. A missing tag becomes `false/0/"missing"`. Unparseable output is retried once with "Return only the JSON object."; truncated output is retried with `max_tokens×2`. A second failure gives `status: error` and nothing is cached. |
| Concurrency | `LLAMA_PARALLEL` model workers, one per llama-server slot. Further work, including work from concurrent requests, queues. |

## Configuration (environment variables)

| Variable | Default | Notes |
|---|---|---|
| `LLAMA_URL` | `http://127.0.0.1:8080` | llama-server base URL |
| `LLAMA_PARALLEL` | `2` | must equal llama-server `--parallel` |
| `LLAMA_URLS` | (unset) | several llama-servers, comma-separated (e.g. one per GPU); work goes to the least busy, and a server that stops answering is skipped while the others carry on |
| `CONFIDENCE_FROM_LOGPROBS` | `1` | confidence = the model's probability of its true/false answer (from token log-probabilities) instead of the number it writes; `0` turns it off |
| `LLAMA_TIMEOUT_S` | `60` | per model request |
| `MAX_EDGE` | `1024` | 768 is about 40% faster but loses hand and hair detail. Use 1280 only for fine-detail tags. Changing it changes image hashes, so the cache misses. |
| `MAX_TAGS_PER_CALL` | `8` | larger tag sets are split across calls on the same image |
| `MAX_TOKENS_BASE` / `MAX_TOKENS_PER_TAG` | `60` / `40` | |
| `MIN_SHORT_EDGE` | `96` | |
| `DEFAULT_THRESHOLD` | `0.7` | |
| `MAX_IMAGES_PER_CALL` | `64` | |
| `FETCH_TIMEOUT_S` / `FETCH_CONCURRENCY` | `10` / `8` | |
| `CACHE_PATH` | `image_detection/data/cache.sqlite3` | inside the package folder, regardless of the working directory |
| `MODEL_ID` | read from llama-server `/props` | the GGUF filename, used in cache keys |


| Check | Result |
|---|---|
| llama-server up, `/health` up, VRAM < 14 GB after warm-up | ✅ 12.3–13.2 GB |
| 50 consecutive classify calls pass the schema, zero retries | ✅ 50/50, 0 retries, ~1.9 s/image |

The 50-call run uses generated shape images (red circle / blue square), so it tests the pipeline, not accuracy on people. Accuracy on the real tags comes from the labeled set.

## Notes

- **Model:** the spec names the official `Qwen3VL-8B-Instruct-Q8_0.gguf`. This setup uses the *abliterated* Instruct variant in `image_detection\LLM\...` with its F16 mmproj. It is the same architecture and the same prompt format. `/health` reports its actual filename, which is also the cache `model_id`, so switching models never serves stale cache entries.
- Do not add a SigLIP pre-filter until the labeled eval has been measured (per the spec).
